# Soft386 R4 — optional Tiny386 80387/x87

## Objective

Enable the optional Tiny386 x87 core in every Soft386 process vessel without
regressing the R3 process hierarchy or the saved-context guest thread scheduler.

## Source intake

The milestone uses the supplied Tiny386 `fpu.c` / `fpu.h` implementation.
Original intake SHA-256 values:

```
aba28c887f8569bbf71752e250500be6b6f378c2c2b1e447a634440a52a4bcca  fpu.c
2f489bf262dbb28e37de16c1f712f46f092c2cd341e5495255186c4237cba9a9  fpu.h
```

R4 makes only a small scheduler-facing addition to those files: opaque
`fpu_state_size`, `fpu_save_state`, and `fpu_load_state` helpers.  The instruction
implementation itself is unchanged.

## Build

`soft386/Makefile` now:

* defines `I386_ENABLE_FPU`;
* compiles `tiny386/fpu.c`;
* links the host math library (`-lm`);
* still rejects a Win64 native bridge build.

Soft386 calls `cpui386_enable_fpu()` before `cpui386_reset_pm_flat()`, therefore
the subsequent CPU reset advertises/initializes an attached FPU and all child
process vessels receive the same feature automatically.

## Guest thread state

R3 already saved integer/control/segment state in `CPUI386_State`.  R4 extends
that state with a bounded opaque FPU image.  `cpui386_get_state()` copies the
current Tiny386 FPU object into the saved context; `cpui386_set_state()` restores
it when a different OS/2 TID is scheduled.

This is process-local.  R3 process vessels already give every OS/2 process a
separate Tiny386 instance, so FPU isolation between processes requires no new
mechanism.

## Regression fixtures

`fpu-soft386.le` executes real x87 instructions:

* FNINIT
* FLD1 / FLDPI / FLDZ
* FADD / FMUL
* FSQRT
* FSIN
* FCOS
* FISTP

and prints:

```
soft386: 80387 x87 math PASS
```

`fpu-thread-soft386.le` deliberately keeps different x87 values in two virtual
OS/2 threads across scheduler switches.  Main preserves ST0=3 while the worker
preserves ST0=2 and prints:

```
soft386: per-thread 80387 state PASS
```

## Fidelity boundary

The supplied FPU implementation warns that it is incomplete.  In particular,
x87 exception behaviour, a true hardware tag word, and full 80-bit precision are
not exact.  Extended-real memory values are accepted but normally converted
through the host `double` representation unless the source is deliberately built
with its optional native float80 path.

That is sufficient to make R4 a useful compatibility milestone, but numerical
edge cases should not be advertised as 80387-bit-exact.
