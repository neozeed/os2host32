# Milestone 30C - rebase bound EMX programs from their retained a.out relocations

M30A/M30B proved that the mixed-mode EMX 0.9d DLL can be loaded, initialized,
and entered under Win32.  The minimal bound `hi.exe` then failed in EMX with:

    Invalid option in .exe file

M30B proved `DosQueryModuleName` was succeeding.  Inspection of the unbound
EMX linker output explains the failure: classic EMX is an i386 a.out program
wrapped by `emxbind`, and the bound LX deliberately contains almost no internal
LX relocations.

For the supplied unbound `hi`:

    magic       ZMAGIC (0x010b), i386 MID 100
    text        0x00009000
    data        0x00001000
    bss         0x00001160
    entry       0x00010000
    text relocs 597
    data relocs 23

The first five text bytes are:

    68 00 00 02 00      push 0x00020000

and the a.out text relocation table contains a 32-bit absolute DATA relocation
at text offset 1.  On real OS/2 the program is mapped at its preferred
0x10000/0x20000 addresses, so no adjustment is needed.  On modern Win32 our
LX arena is commonly moved to 0x01000000/0x01010000, while the hard-coded
0x00020000 remains unchanged.  EMX therefore receives the wrong executable
information pointer and diagnoses its contents as an invalid embedded option.

## M30C proof mechanism

M30C adds an opt-in sidecar rebasing pass to `os2host32`.

Set:

    OS2_EMX_AOUT_SIDECAR=1

For `hi.exe`, os2host32 then opens the unbound sidecar `hi`, validates that its
a.out TEXT and DATA+BSS sizes exactly match LX objects 1 and 2, validates the
entry/base relationship, and consumes its relocation tables.

It rebases only 32-bit, non-PC-relative, non-external TEXT/DATA/BSS relocation
sites.  PC-relative references remain correct because os2host32 preserves the
relative LX layout.  External references are left to the existing LX import
fixups generated by emxbind.  Absolute-constant relocations are not changed.

For the supplied `hi` the expected inventory is:

    applied absolute internal relocations : 372
    skipped internal PC-relative          : 245
    skipped external                      : 1
    skipped absolute constants            : 2

With the usual relocation delta of 0x00ff0000 the entry operand becomes:

    push 0x00020000  ->  push 0x01010000

## Why a sidecar first?

`emxbind` keeps enough of the a.out header in the bound executable to describe
TEXT/DATA/BSS, but the bound image has its a.out relocation sizes cleared.  The
original unbound linker output still has the complete relocation tables.

Using that file gives us a deterministic proof before changing emxbind itself.
If this gets `hi` through startup, the cleaner later design is to enhance the
Win32-rebuilt emxbind so it either:

* emits equivalent LX internal fixups, or
* retains a compact relocation block that os2host32 can consume directly.

No x86 instruction scanning should be necessary.

## Build

Use the same i686 MinGW environment as M30B:

    make clean
    make tools compat

## Test

This package includes the uploaded unbound `hi` sidecar.  Copy the exact
OS/2-tested bound executable and EMX DLL into the root of the build directory:

    hi.exe
    emx.dll

Then run:

    m30c-emx-hi-test.cmd

Expected new diagnostic lines include approximately:

    M30C EMX a.out   : hi ZMAGIC text=00009000 data=00001000 bss=00001160 relocs=597+23
    M30C EMX rebase : delta=00FF0000 applied=372 pcrel=245 external=1 abs=2
    M30C EMX entry  : first DATA operand 00020000 -> 01010000

The next result after those lines is the important one.  The target is simply:

    hi

If it advances further but hits a trap/API, capture the complete output from
`M30C EMX a.out` onward.

## Explicit sidecar path

Instead of `1`, `OS2_EMX_AOUT_SIDECAR` may contain an explicit path:

    set OS2_EMX_AOUT_SIDECAR=C:\emx\demo\hi

This is useful when keeping the linker output outside the test directory.
