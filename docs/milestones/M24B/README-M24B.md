# Milestone 24b — process-environment unification\n\nM24 exposed an important Win32 CRT compatibility detail. `cmd32os2` implements\n`SET`, `SETLOCAL`, and `ENDLOCAL` with the Win32 process environment APIs, while\nM23's reconstructed `MSEnvVar` initially used the C runtime `getenv()`.  Some\nWin32 C runtimes maintain a separate `environ` copy, so a successful `SET` could\nbe invisible to subsequent `%NAME%` expansion.\n\nM24b changes `MSEnvVar` on Windows to use `GetEnvironmentVariableA`, matching\nthe environment store modified by `SetEnvironmentVariableA`.  The portable\nnon-Windows parser regression continues to use standard C `getenv()`.\n\nExpected regression:\n\n    set M24_LOCAL=outer\n    echo before SETLOCAL: %M24_LOCAL%\n    setlocal\n    set M24_LOCAL=inner\n    echo inside SETLOCAL: %M24_LOCAL%\n    endlocal\n    echo after ENDLOCAL: %M24_LOCAL%\n\nExpected output:\n\n    before SETLOCAL: outer\n    inside SETLOCAL: inner\n    after ENDLOCAL: outer\n\nThe example batch file's `status7` test assumes `status7.exe` is reachable from\nthe current directory/PATH.  Running the script while current directory is the\n`examples` subdirectory will therefore not find the executable built in the\nparent directory.  That is a test-layout issue, not an `IF ERRORLEVEL` failure.\n
